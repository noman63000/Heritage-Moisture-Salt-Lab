EXECUTION ADD-ON 1.1.0 / SCIENTIFIC CORE 1.2.0-1.2.1 UNCHANGED

All-cases Parallel & Resume
Verification and installation

Implemented: choose 1-21 independent workers, or All selected. Existing completed outputs are retained; compatible partial runs resume in their original folders. This package does not install a new physical model.
Scope: the current four live calculations on the user's computer were not available here. The tests below use short, explicitly synthetic-forcing fixtures, the real supplied brick functions and an earlier supplied R00 checkpoint for arithmetic probes. No new multi-decade research results or guaranteed hardware speedup are claimed.

1. What the controls do

ControlBehavior
All selected - up to 21 at onceStart each eligible, unfinished selected case in its own spawned process, up to 21 active workers. Starts are slightly staggered to avoid an import burst. Low-memory/disk guards may hold new starts.
Select remainingExclude verified completed results. Preserve partial-run progress; do not infer success from a queue position.
Apply limit to active queueRaise or lower the target without changing model inputs. A lower target does not kill current workers; pause individual cases or pause all to release slots sooner.
Pause this case / Pause ALL safelyWait for the next committed chunk for affected active workers. Other independent cases continue after an individual pause. Re-select paused cases after the queue stops to resume them.
Progress and historyPer-case live/saved hours, recent pace and diagnostics; aggregate recent pace, RAM/disk availability; CSV and JSON exports. Failed/blocked outcomes are retained across later queues under matching input identities.

3. Protection of existing work

The installer checks the supported scientific file identities, refuses active console/case locks, creates a full verified copy of projects, and audits checkpoint/state checksums plus committed row continuity. The add-on is staged before replacement; old add-on/launcher files are saved for rollback. Scientific files, configuration, material/climate, preparation certificates and outputs are not replaced by installation.

The backup is created only when the installer runs on the user's computer. It is a same-drive backup, not protection against loss of that drive. No tool can recover a computation that was never saved.

Normal resumed execution advances existing checkpoints. Previously committed chunks and completed scientific outputs are not rewritten. The original workflow may refresh provenance metadata for a partial run; the pre-installation version remains in the backup. No fixture PASS records or test states are installed into a live project.

4. Installation

  1. In the current dashboard, choose Pause safely after next checkpoint or Pause ALL safely. Wait for all workers to stop; then close the terminal and Chrome tab.
  2. Extract this update ZIP into its own folder. Do not manually copy it over the original application.
  3. Run INSTALL_ALL_CASES_WINDOWS.bat.
  4. In the file picker, select the original START_FAST_WINDOWS.bat you currently use. The original START_WINDOWS.bat is also accepted. Select the actual file, not this update folder.
  5. Wait for the verified-backup and installation-complete messages. If validation fails, stop and inspect the log; do not delete saved work to force acceptance.
  6. Restart START_FAST_WINDOWS.bat in the original application. The header should show Add-on 1.1.0. Scientific version 1.2.1 is not downgraded.
  7. Verify the saved-hour counters. Choose Select remaining, choose All selected - up to 21 at once, and click Resume / run selected cases.

Keep only one Heritage Lab console open. Matching QA/spin-up/freeze remain valid because the scientific files and project settings are unchanged. No new Python dependencies, climate download or material import is required.

5. Performance and resource limits

More processes do not create more CPU cores. With high concurrency, a single case can slow down even if aggregate completion improves; excessive concurrency can also reduce overall throughput. Compare combined recent pace and RAM availability rather than assuming All selected is always fastest. No speedup factor over the user's existing four-worker workload has been measured.

Native numerical-library thread counts are limited to one per process. The original BDF integration, numerical tolerances, source functions, mesh, event handling and optional exact-cache self-check remain. This is not a GPU port.

New starts wait below 2 GB free disk or below the larger of 2 GB / 5% available physical RAM. Critical disk below 512 MB or RAM below the larger of 512 MB / 1% requests a safe pause. These sampled guards are not hard memory limits, temperature control, or a guarantee against restart or operating-system failure. Reopen the launcher and select remaining after a restart; this add-on is not a Windows startup service.

6. Scientific restrictions remain

No-ice and other model-scope checks are retained. A blocked climate case is shown as BLOCKED, not completed. More worker slots do not solve unsupported physics. No scientific threshold is weakened to admit additional cases.
