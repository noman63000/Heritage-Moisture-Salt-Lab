Heritage Moisture & Salt Lab 1.2.1 — overnight preparation verification

Purpose: make the unattended preparation workflow unambiguous in the dashboard. The single overnight button visibly performs Numerical QA for selected cases → shared R00 water/heat spin-up → Freeze reduced inputs.

What changed

  • The Run & check page now shows the three automatic stages as 1/3, 2/3 and 3/3.
  • The primary button is labelled Run QA → Spin-up → Freeze overnight.
  • The page explicitly states that the manual Spin-up and Freeze buttons do not need to be pressed after the overnight queue starts.
  • The morning summary separately displays QA PASS/FAIL counts (including failed case IDs), spin-up status, and freeze status.
  • Final job messaging explicitly reports all three stages.

What did not change

The scientific 1.2.0 implementation files used in the project physics hash—solver.py, material.py, face_integral.py, climate.py, workflow.py, project.py and common.py—are not modified by this update. The installer refuses to proceed if those target files do not match the tested 1.2.0 release.

Therefore this update does not change material functions, physical settings, numerical water-face method, QA threshold, spin-up equations or climate data. Existing valid QA/spin-up/freeze controls are preserved byte-for-byte.

Expected overnight behavior

  1. Select one or many R00–R20 cases.
  2. Click Run QA → Spin-up → Freeze overnight.
  3. Each selected case is QA-tested sequentially. A case-specific failure is saved and the queue continues.
  4. After the QA sweep, one shared R00 water/heat spin-up is run or reused automatically.
  5. Freeze is attempted automatically when its prerequisites are satisfied.
  6. prep_queue.json and the dashboard summary show the final three-stage status.
